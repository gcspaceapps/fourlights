# web/: the front end

**What lives here:** Vite + TypeScript (no framework), `index.html`, and in `src/`: `main.ts` (page wiring, URL-hash state, theme switch), `lights.ts` (the four lights, usable days, every threshold), `chart.ts` (Sun-Path Chart, SVG), `planner.ts` (Slip Planner), `battery.ts` (Survive the Night: presets, simulation, strip chart), `icons.ts` (Phosphor icons for the four lights, and the info tips: add `data-info="..."` to any element in `index.html`, or call `infoTip()`), `segmented.ts` (turns a short `<select>` into a button group; the hidden select stays the source of truth, so set its value and dispatch `change`, never the buttons), `shortcuts.ts` (keyboard shortcuts and the Ctrl+/ help dialog; the `SHORTCUTS` list in `main.ts` drives both), `map.ts` (the south-pole site map over `public/map/south-pole-hillshade.jpg`, made by `make map` in `pipeline/`), `summary.ts` (the planner's precomputed figures: `scripts/build-planner-summary.mjs` runs it in Node to write `public/data/planner.json`, and the planner reads that file; keep its imports with explicit `.ts` extensions), `data.ts` (lazy JSON loading, including `public/data/reviews.json`, the AI-written site reviews), `types.ts` (data contract), `style.css` (design tokens, dark and light). Plus `public/data/`, the published JSON from the pipeline, served at `/data/...`. Builds to `web/dist`, which the Worker serves.

**Entry points:** `index.html` → `src/main.ts`. Data types: `src/types.ts` (written in S1 from the data contract in `../_shared/stack.md`).

**Run / test:** `npm run dev` at the repo root (build + `wrangler dev`), or `npm run dev -w web` for Vite alone. `npm run check` before every commit. `npm run check:real-data` (part of `npm run deploy`) fails if any `fake-` fixture is in `public/data/`; `npm run fake-data` regenerates the three fixtures for UI work, never to be committed.

**Views:** `data-view` on `<html>` is `mission`, `explore` or `learn` (switch in the header, `V` key, `v=` in the URL, remembered per browser). Mark content with class `v-explore` (hidden in Mission), `v-learn` (Learn only) or `v-mission` (Mission only); the rules are in `style.css`. Teaching text lives in `index.html` and must stay factual and sourced from the same data.

**Tests:** unit tests in `tests/` (`npm test`, part of `npm run check`): the light rules, the disc, the battery, the planner sentence and summary, the AI-reply validator, and the demo scenario on the real files. End-to-end tests in `../e2e/` (`npm run test:e2e`, Playwright with the installed Chrome, about 30 s, **not** part of check): the demo scenario through the UI, the chart, views, theme, shortcuts, map, the question box with the model stubbed, the API, and the password gate on a second local Worker. Run them before a deploy that changes behaviour.

**Rules:** the four lights, mission window and usable days follow `../_shared/concept.md` exactly; thresholds are named constants in one file. The browser does the maths (the Worker can't: 10 ms CPU). Its own clean design (Space Apps colours not required, see `../_shared/brand.md`), 4.5:1 contrast, keyboard-usable. Phones are a design goal, not a priority: nothing should break, wide views scroll sideways. Each NASA dataset is named on screen, and anything that is our own definition or an illustrative number says so in its info tip.

**Touches:** `public/data/` is written by `pipeline/` (see `../_datasets/`). If you change the data shape, change `../_shared/stack.md`, `src/types.ts` and the pipeline together.
