# api/: the Worker

**What lives here:** the one Cloudflare Worker (Hono, TypeScript strict), `src/index.ts`. Config is `../wrangler.jsonc` at the repo root (obscure Worker name, served at fourlights.gcsa.space with workers.dev off, `account_id` pinned, static assets from `web/dist`).

**Entry points:**
- `GET /api/health` → `{ok, time}` (the Worker's clock, to show it is answering)
- `POST /api/ask` `{q}` → `{ok, intent: {date, slip_days, window_days, site}}`: Workers AI (binding `AI`, model in `src/intent.ts`) turns a typed question (≤ 200 characters) into planner settings. The reply is validated field by field in `src/intent.ts` (tested in `web/tests/`); the model never answers the question. 400 for empty or long input, 422 if nothing usable, 503 if the model fails
- `GET /etiles/<wac|lola>/<z>/<row>/<col>` → a NASA Moon Trek tile for the 3D map (`src/etiles.ts`, cards `_datasets/nasa-lro-*`). 404 outside the grid (WAC z0 to 8, LOLA z0 to 5; 2^(z+1) columns by 2^z rows), 502 if NASA fails. Cloudflare Cache API in front (URL-only key, behind the password gate; per data centre, custom domain only), one shared fetch per tile at a time, `Cache-Control: public, max-age=604800`. No R2: a cold data centre re-fetches from NASA
- `GET|HEAD /qgis/<file>` → the QGIS pack's static files (`web/public/qgis/`), cut to the `Range` asked for (`src/ranges.ts`): QGIS reads through GDAL's `/vsicurl/`, which needs a 206 for a range, and Workers static assets always send the whole file. Only this folder is sliced. `GET|HEAD /qgis/r2/<key>` → the three 20 m rasters from the R2 bucket bound as `QGIS_BUCKET` (bucket `q7m3-qgis-poc`, private; R2 reads the range itself). Both are behind the same password gate. Tests: `tests/ranges.test.ts`, and on the real Worker in `e2e/api.spec.ts`
- **Shared projects** (`src/project.ts`, `src/project-state.ts`; the whole design is in `../_shared/shared-projects.md`): one SQLite-backed Durable Object (binding `PROJECTS`, class `Project`, migration `v1`) per project, named by its uuid. `POST /api/projects` `{name, sites?, data?, view?}` → 201 `{ok, project}` (the Worker makes the uuid; 400 without a name of up to 60 characters); `GET /api/projects/<uuid>` → the project, 404 if there is none; `POST /api/projects/<uuid>/commands` a command (what an MCP tool calls; `addSite` avoids the published site ids); `GET /api/projects/<uuid>/ws` the live WebSocket (426 without an upgrade, 429 past 20 people). There is no list route, on purpose: a project is found only by its uuid
- **MCP server** (`src/mcp.ts`, design and tool table in `../_shared/shared-projects.md`): `POST /mcp` and `POST /mcp/<uuid>` speak MCP over stateless Streamable HTTP (JSON-RPC; `GET` is 405). Tools read and change one project through the Durable Object's `snapshot()` and `command()`, and answer questions from `/data/planner.json` and `/data/reviews.json`. Behind the same password gate
- everything else → the static assets (`web/dist`, including `/data/...` JSON)
- **Computing a project's site** (`src/pipeline.ts`; the pipeline side is `../pipeline/CONTEXT.md`, "Where it runs"): a site added to a shared project is only a name and a position until someone presses "Compute this site". Then:
  - `POST /api/projects/<uuid>/sites/<site>/compute` → the Durable Object marks the site `computing` and keeps a one-time token; the Worker asks Fly's Machines API to start a machine from the pipeline image with the site, the token and the address to send the result to. 202 when started; 409 if the site is unknown, north of 80°S, already has data, already running, or the project has its 5 computed sites; 429 when the day's runs for the whole site are used up; 502 (and the site marked `failed`) if the machine did not start; 503 when the feature is switched off.
  - `PUT /api/pipeline/<uuid>/<site>` with `Authorization: Bearer <token>` → the machine's site file (up to 2 MB, must be for that site) is stored in R2 under `projects/<uuid>/sites/<site>.json` (the bucket bound as `QGIS_BUCKET`), and the site becomes `ready` for everyone on the project. `POST .../failed` with the token marks it `failed`. A token works once.
  - `GET /api/projects/<uuid>/sites/<site>.json` → the stored file; the page loads it in place of `/data/sites/<site>.json`.
  - **Switched on by four values** (`wrangler secret put`; unset any one and the compute route answers 503 and nothing else changes): `FLY_API_TOKEN` (a Fly token limited to the pipeline app: `fly tokens create deploy --app <app>`), `FLY_APP`, `FLY_IMAGE`, `FLY_VOLUME` (the volume's id). Optional: `FLY_REGION` (default `syd`), `FLY_API_BASE` (tests and local runs). **To switch it off in seconds, no deploy:** `npx wrangler secret delete FLY_API_TOKEN`.
  - Limits: one run at a time (the volume mounts on one machine); 5 computed sites per project (`MAX_COMPUTED` in `src/project-state.ts`); **100 runs a day (UTC) across every project** (set high on purpose, so a judge is not turned away), counted in one Durable Object named `run-counter` (no project can have that name) and changed without a deploy by `printf 30 | npx wrangler secret put COMPUTE_DAILY_MAX`, which lowers it to 30 (0 stops new runs); a run that never started is not counted; a run not heard from in 30 minutes may be asked for again. The compute route is not in the WAF rate-limit rule (the free plan's one rule is on `/api/ask` and `/api/projects`); the limits above are what bound the cost. Not done: removing a site does not delete its stored file (Steve will clear old ones later; an R2 lifecycle rule on the `projects/` prefix would do it with no job, but a project whose file expired would show a ready site that fails to load, so the status needs resetting too); the MCP tools do not start a run or answer from a computed site's file.
- **Rate limit (Cloudflare WAF, not in this code):** one rate-limiting rule on the `gcsa.space` zone blocks an IP for 10 s after 10 `POST`s in 10 s to `/api/ask` or `/api/projects` on `fourlights.gcsa.space` (answers 429). It caps Workers AI spend and project creation; pages, data, `/qgis`, `/mcp` and the other project routes are not limited. The free plan allows one such rule with a 10 s window. See or change it: `cf rulesets list --zone gcsa.space` (phase `http_ratelimit`), or the dashboard under Security, WAF, Rate limiting rules.
- **Future, not built: invisible Turnstile on `/api/ask`** (Steve, Sun 15 Nov: keep an eye on it). The rate limit still lets one IP ask about 60 times a minute, and does nothing against many IPs. If `/api/ask` gets abused (watch Workers AI usage in the dashboard and 429s under Security, Events), add Turnstile in invisible mode to that one route:
  - Page: load the Turnstile script, get a token when a question is submitted, send it with the `POST`. Invisible mode needs a visible line linking Cloudflare's privacy policy and terms beside the Ask box.
  - Worker: check the token with siteverify before the Workers AI call; 403 if it fails. Only verify while the secret is set (as the password gate does with `SITE_PASSWORD`), so deleting the secret turns it off in seconds with no deploy.
  - Setup: a Turnstile widget for `fourlights.gcsa.space`; site key in the page, secret key by `wrangler secret put`. Unit and end-to-end tests use Cloudflare's always-pass test keys.
  - Only `/api/ask`: `/api/projects`, `/mcp` and `/qgis` are used by MCP clients and QGIS, which cannot answer a challenge. Some real visitors (privacy browsers, VPNs) fail the silent check and would get an error from the Ask box.
  - Cheaper first steps: narrow the WAF rule to `/api/ask` with a lower threshold, or a daily cap on asks in the Worker. Not Cloudflare Access: the demo must open with no login.
- **Weekend password gate:** while the Worker secret `SITE_PASSWORD` is set, every request (pages, data, API) needs HTTP Basic Auth, user `fourlights`. `run_worker_first: true` makes the assets go through it too. **To open the site** (late Sunday, before the private-window link checks): `npx wrangler secret delete SITE_PASSWORD`. No code change or redeploy needed. Locally, `wrangler dev` has no password unless `.dev.vars` sets one.

**Changing the project state:** the checklist (state, validators, page wiring, MCP tools, tests, docs, and when a Durable Object migration in `wrangler.jsonc` is needed) is in `../_shared/shared-projects.md`, "Keeping the project state up to date". Adding a key is safe for existing projects (defaults are merged on load); renaming or removing one is not.

**Run / test / deploy:** `npm run dev` (builds web, then `wrangler dev` on http://localhost:8787). Deploy per the deploy rule in `../_shared/how-we-work.md`: Steve or Matt, from an up-to-date clean `main`, `npm run deploy`. A second agent session: `npx wrangler versions upload` (the preview URL is password-gated too).

**Locally:** `wrangler dev` also needs a Cloudflare login for the Workers AI binding; the Durable Object itself runs locally.

**Limits (Workers Free):** 10 ms CPU per request. The Worker routes and serves; no maths here.

**Touches:** no datasets directly. If you change routes, check `web/src/` fetch paths and the README.
